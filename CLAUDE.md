# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

RallyVision (formerly Good-Tennis) is a computer-vision tennis match video analyzer: it detects players and the ball frame-by-frame, maps image coordinates to real court coordinates, tracks rallies and movement stats, detects ball bounces, and renders an annotated output video plus data files. It is a CLI application, not a library — there are no tests, no linter config, and no build step.

Documentation is bilingual: `README.md` (Chinese, primary) and `README_en.md` (English). User-facing strings and console output are also bilingual; keep both in sync when changing them.

## Commands

```bash
# Setup (uv manages Python and all dependencies; FFmpeg must be on PATH)
uv sync

# Run analysis (the only entry point)
uv run main.py --video-path videos/demo.mp4 --template-path templates/demo.png

# Headless / non-interactive run (no OpenCV windows, no tkinter file picker)
uv run main.py --video-path videos/demo.mp4 --template-path templates/demo.png --display false

# Switch player detection from YOLO person boxes (default) to pose estimation
uv run main.py ... --player-detector pose --pose-family rtmpose
```

Model weights are not in the repo — download them from the GitHub Releases page into `weights/` (defaults: `weights/tennis-ball.pt`, `weights/yolo26s.pt`, `weights/yolo11s-pose.pt`). Startup fails with a clear error if the ball model is missing.

Dependencies are declared in `pyproject.toml` (uv-managed, Python 3.9–3.11, CPU torch/onnxruntime); GPU users manually install CUDA wheels (see README).

## Architecture

The whole pipeline runs through `TennisAnalysisSystem` in `tennis_analysis/system.py` — read it first. `main.py` only parses args and instantiates it.

Heavy imports (cv2, torch, ultralytics, all submodules) are deferred: `load_runtime_dependencies()` in `system.py` imports them into module-level globals _after_ argparse runs, so `--help` stays fast. New modules used by `system.py` must be registered there, not imported at the top of the file.

### Per-frame pipeline (`process_video` → `_process_frame`)

1. **Court-view gating**: each frame is template-matched (`cv2.matchTemplate`) against the court template image at reduced width. Non-court frames (replays, close-ups) skip all detection. Consecutive court/non-court frame counts drive **rally detection**: N consecutive court frames start a rally, N non-court frames end it and reset per-rally stats and the ball trajectory.
2. **Player detection** inside an ROI expanded from the court corners, cached and re-run every `--player-detect-interval` frames. Two backends behind one interface: `detection/yolo_person.py` (person boxes, bottom-center = player position, optional botsort/bytetrack MOT) or `detection/rtmpose.py` / `detection/yolo_pose.py` (pose keypoints).
3. **Ball detection** (`detection/tennis_ball.py`, YOLO) — raw positions are written to data; the clean trajectory is produced later in post-processing.
4. **Tracking** (`tracking/player.py` `PlayerTracker`): player identity is **`upper` / `lower` half-court**, not track IDs — MOT `track_id` is only a weak matching bonus; continuity of court coordinates is the primary signal. Maintains per-rally and per-match distance/speed stats and writes one JSONL record per court frame.
5. **Visualization** overlays (`visualization/`): skeletons/boxes, trajectories, stats panel, minimap. Frames go to an OpenCV window (if `--display true`) and a temp video file.

### Post-processing (after the frame loop, in `_cleanup`)

- **Bounce detection** (`analysis/bounce.py` `BounceDetector.process_detections`) re-reads `detections.jsonl`, cleans/interpolates the full ball trajectory, scores bounces (rule-based by default, optional classifier via `--bounce-classifier`), rewrites `detections.jsonl`, then re-annotates the temp video with the clean trajectory and bounce markers.
- **Audio merge** (`media/video_audio.py`, FFmpeg) produces the final `detect_<name>.mp4`.
- Position heatmaps/scatter plots are generated by `main.py` afterward — note `visualization/player_positions_zh.py` and `player_positions_en.py` are near-duplicate files selected by `--language`; changes to one usually need mirroring in the other.

### Court coordinate system

`court/mapper.py` `CourtMapper` holds a homography from 4 manually-clicked or auto-detected doubles-court outer corners (order: top-left, top-right, bottom-right, bottom-left) to a standard court in meters (10.97 × 23.77). Everything downstream (speeds, distances, minimap, heatmaps) works in court meters. `court/auto_detector.py` attempts automatic corner detection with an interactive accept/reject preview; `--court-detection` picks manual/auto/auto-fallback.

### Outputs and caching

All outputs go to `outputs/<video_name>/`: `metadata.json`, `detections.jsonl` (per-frame records, schema version in `data/writer.py`), `bounce_events.json`, `cleaned_ball_trajectory.json`, the annotated video, and `court_annotations.txt`. **`court_annotations.txt` is a cache** — corner annotation is skipped on reruns while it exists; it must be deleted when the camera angle or template changes.

### Gotchas

- Boolean CLI flags are string-valued: `--display false`, not `--no-display` (see `main.py`).
- Interactive steps (tkinter template picker, OpenCV annotation/confirmation windows) block headless runs; always pass `--template-path`, and use cached `court_annotations.txt` or pre-seed it to avoid annotation prompts.
- `person_tracker != none` requires the `lap` package (validated at startup).
